# 学习路线：从第一次摸板子到做完一道赛题

两个约束决定这条路线的形状：

1. **比赛只有 4 天，视觉只是其中一个子系统。** 所以目标是培养"能在时间压力下集成和调试"的人，
   不是"能写出漂亮视觉代码"的人。
2. **读者里可能有人从没碰过嵌入式板子。** 所以**每个阶段都以一个能看见的物理结果收尾**，
   而不是以"看懂了"收尾。

总量 **70–110 小时**。阶段 0–3 约 30 小时，是**最低可用**的备赛量；阶段 4–5 才区分冲奖。

```
阶段0 环境 ──→ 阶段1 图像基础 ──→ 阶段2 特征与几何 ──→ 阶段3 串口+闭环
  2-4h          6-10h              10-16h              8-12h
                                                           │
                        阶段5 赛题实战 ←── 阶段4 AI/kmodel ←┘
                          20-40h           12-20h
```

> 每个阶段的"读什么"都指向本仓库的具体文件；"练习"都带**能判定过没过**的标准。
> 没有验收标准的练习等于没练。

## 阶段 0 · 环境（2–4 小时）

**读**：[01_getting_started.md](01_getting_started.md)、
[庐山派快速上手](https://wiki.lckfb.com/zh-hans/lushan-pi-k230/quick-start.html)
**跑**：`01_basics/01_camera_open.py`（⚠️ 该文件当前有一处 `Sensor(channe=)` 拼错，见
[已知问题 P0-3](02_known_issues.md)，改一个词就有画面 —— 这本身就是第一个练习）

| # | 练习 | 验收标准（做到什么算过） |
| --- | --- | --- |
| 0.1 | 烧好 CanMV 固件并在 IDE 里确认版本 | IDE 能报出版本号，且你知道自己在 v1.2 还是 v1.3+（这决定后面哪些文件能跑） |
| 0.2 | 跑通摄像头，看到实时画面 | 有画面、≥15 FPS，**并且按停止后不用断电就能再跑一次** |
| 0.3 | 把 `DISPLAY_MODE` 在 `LCD` / `HDMI` / `VIRT` 之间各切一次 | 三种都在正确的输出上以正确分辨率出图；能说出 `ALIGN_UP(w,16)` 为什么存在 |
| 0.4 | **故意弄坏它**：删掉 `MediaManager.deinit()`，连跑两次 | 第二次失败，且你能凭说出报错和修法 |

0.2 和 0.4 是这一阶段真正的产出。`os.exitpoint()` + `MediaManager.deinit()` 这套契约
是 CanMV 上最容易被忽略、又最影响体验的东西 —— 你会在阶段 1 看到 `05_cv_lite/`
27 个文件全都缺它，那时你会感激现在学会了怎么检查。

## 阶段 1 · 图像基础（6–10 小时）

**读/跑**：`01_basics/02_drawing.py` → `03_find_rectangles.py` → `05_find_circles.py`
→ `06_color_blobs_and_lines.py` → `07_color_tracking.py`；
`05_cv_lite/01_grayscale_binary.py` 到 `14_rgb888_histogram.py`

| # | 练习 | 验收标准 |
| --- | --- | --- |
| **1.1** | **同一个物体，在三种光照下（日光 / 室内灯 / 手机手电）各用 IDE 阈值工具标一次** | 记下**三组不同的阈值**，并用一句话说清为什么不同 |
| 1.2 | 在一个有噪声的目标上依次跑腐蚀、膨胀、开、闭、顶帽、黑帽、形态学梯度 | 交出一张"哪个操作去掉了哪种瑕疵"的表，并指出空心双层框目标该用哪个 |
| 1.3 | 让 `07_color_tracking.py` 追踪指定物体，同时拒绝一个颜色相近的干扰物 | 调 `pixels_threshold`/`area_threshold` 让干扰物永不胜出，且三种光照下都成立 |
| 1.4 | 量一次"有每帧 print"和"无每帧 print"的帧率差 | 交出一对具体数字 |

**1.1 是整条路线里最重要的一课。** 后面所有"赛场识别失效"都源自同一个事实：
**阈值是环境量，不是配置量。** 现在把它体验透，比在赛场上第一次遇到强一百倍。

顺带学会一件事：`05_cv_lite/` 里两套系列覆盖同样的算法但**已经分叉**
（白平衡有带参 `_ex` 版和无参版两种 API）。养成"看签名不看文件名"的习惯。

## 阶段 2 · 特征检测与几何（10–16 小时）

**跑**：`01_basics/04_find_line_segments.py`、`08_find_barcode.py`、`09_find_qrcode.py`、
`10_find_apriltag_basic.py`、`12_find_apriltag_full.py`、`11_line_following.py`；
`06_practice/03_nested_rect.py`、`04_triangle.py`、`05_polygon_from_lines.py`、`06_curve_recognition_WIP.py`

| # | 练习 | 验收标准 |
| --- | --- | --- |
| 2.1 | 用胶带在地上贴一条巡线路，让 `11_line_following.py` 的 `get_regression` 跟住 | 过一个十字、一个 90° 直角不丢线；并能说出 `get_regression` 为什么优于逐像素扫描 |
| 2.2 | 打印一个 AprilTag 装到目标上，让 `12_find_apriltag_full.py` 报 ID | 3 个距离 × 2 个角度都正确 |
| 2.3 | **自己实现一遍"嵌套矩形"判别**，再和 `03_nested_rect.py` 对比 | 你的版本能区分单层框和双层框目标 |
| **2.4** | **读 `06_practice/06_curve_recognition_WIP.py`，在看任何说明之前，先把它的缺陷自己找出来写下来** | 独立找出 8 个里的至少 5 个 |
| 2.5 | 给 `04_find_line_segments.py` 传一个超出画面宽度的 roi（文件里现在就是 `(0,0,480,240)` 而画面是 400 宽） | 看到越界报错，并说出为什么 roi 应该从分辨率变量推导 |

**2.4 是全课程价值最高的一个练习。** 它是一个真实代码库、带着一串互相掩盖的 bug
（阈值让每个像素都命中 → 全图一个 blob；偶数高斯核抛异常 → 被宽泛 `except` 吞掉 →
曲线"永远检测不到"却一声不响；就地 `to_grayscale` 污染显示缓冲；在未归一化的像素坐标上
手写 Cramer 法则解二次拟合，`sum(x⁴)` 到 1e15，解出来是噪声）。
**能找出这些，就是比赛里能修好的能力。**

顺带记住它慢的真正原因：纯 Python 双重循环 `get_pixel` 扫 800×480 ≈ 每帧 38 万次调用。
**这条不是调参数能救的** —— 像素级的活必须交给固件的 C 实现。

## 阶段 3 · 串口与闭环控制（8–12 小时）

**跑**：`02_data_collection/03_uart_test.py`；`06_practice/01_all_in_one.py`、`02_key_switch_ui.py`、
`08_color_line_following.py`；`07_contest/2023_E_laser/reference_gimbal/`；
只读 `other_boards/stm32/`；查 [02_known_issues.md](02_known_issues.md) 的 P3-1

| # | 练习 | 验收标准 |
| --- | --- | --- |
| 3.1 | 把 K230 的 UART2（GPIO11 TX / GPIO12 RX）接到 USB 转串口或 STM32，做回环 | 发的字节数 = 收的字节数，且你能在实体接线上指出**交叉连接**和**共地** |
| 3.2 | 仓库里有 4 套互不兼容的帧格式，为每一套各找出一个"发它的文件" | 4 套全对上；并能解释为什么 `other_boards/stm32/snippets/uart_rx_tx.c` 会丢掉 `06_practice/` 发的每一帧 |
| **3.3** | **实现字节流重同步**：改成扫描帧头、校验长度和帧尾、不匹配就前进一字节重扫 | **故意在数据流中间拔掉一次 TX 线再插回**：现有写法此后再也收不到任何命令，你的新写法在收到下一个完整帧时自动恢复 |
| 3.4 | 闭环：像素误差 → 云台指令 → 目标重新居中 | 从 100 像素偏差在 2 秒内收敛且不振荡；然后加一个干扰物，确认不会锁到它上面 |
| 3.5 | 复现 P2-7：把负的 PID 输出用 `'<BHH'` 打包 | 亲眼看到 `struct.error`，并说出两种修法和 MCU 各需要怎么配合 |

3.3 值得单独强调。全仓库的接收写法都是"一次读满 N 字节才算一帧"，
**丢一个字节就永久错位、且永不自愈**，表现是"识别偶尔不对" —— 这是最难查的一类故障，
也是这个项目最容易在赛场上翻车的地方。

## 练法（比练什么更重要）

1. **永远要有实体目标。** 仿真（`06_practice/08_line_following_sim.html`、
   `07_contest/laser_drawing/sim/ui_simulation.html`）只能建立直觉 —— 而且它们的阈值模型
   和板子上的**不一致**。传感器噪声、曝光、白平衡才是真正的学习对象。
2. **一次只改一个变量，并记下来。** 用一个 markdown 当实验本：日期 / 光照 / 阈值 / FPS / 结果。
   [已知问题 P1-2](02_known_issues.md) 那个"滑块默认值和真实阈值分叉"能活一年，
   就是因为没人记录哪组阈值是真的。
3. **先读 `iterations/` 和 `error/`，再读 `result/`。** 那 9 个迭代文件是一条单变量实验序列，
   解释了可用版本为什么长成那样。只读最终版学到的是照搬。
4. **每次调试限时 30 分钟，然后开始加仪表。** 2025 高精版里三个必崩点被一个只打印异常文本、
   不带 traceback 的 `except BaseException` 藏了一整年。
   要养成的习惯是：**卡住时第一件事是加 `sys.print_exception(e)`，不是改逻辑。**
5. **练"重新标定"，而不只是练"识别"。** 赛场上你没有时间调算法，你有时间调阈值。
   把这个动作练到三分钟以内。

## 队友分工建议（4 人队）

视觉只是一个人手上的活，别让它吃掉全队的进度：

| 角色 | 干什么 | 对应本仓库 |
| --- | --- | --- |
| 视觉 | 标定、识别判据、阈值重标定演练 | `01`/`05`/`06` |
| 控制 | MCU 固件、云台/电机闭环、**和对端确认串口帧格式** | `other_boards/stm32/` |
| 结构+电源 | 靶标制作、支架、供电（按云台**堵转电流**选，不是标称） | — |
| 论文/测模 | 全程记录实测数据 | 每人一个实验本 |

⚠️ 最容易出的事故：**两个人各改一版帧格式，谁都不知道。**
赛前务必把串口格式定成一份写死的表格，贴在纸上（见
[05_competition_checklist.md](05_competition_checklist.md)）。
